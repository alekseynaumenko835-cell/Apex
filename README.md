# APEX — server edition

Тот же движок, что был в браузерном apex.html (paper trading, Binance USDⓈ-M
futures, тренд-скан по ~100 монетам), но теперь торговый цикл крутится на
сервере 24/7, а не только пока открыта вкладка в браузере. Смотреть статус —
с телефона, по ссылке.

**Всё ещё paper trading.** API-ключей нет, реальных ордеров нет, депозит
виртуальный ($10 000 стартовый баланс из CFG). Ничем не рискует.

## Локальная проверка (необязательно, но полезно перед деплоем)

```bash
npm install
npm start
```

Открой `http://localhost:3000` — должен появиться дашборд, через несколько
секунд — первый скан в логе.

## Деплой: GitHub + Railway

### 1. Залить в GitHub

```bash
cd apex-server
git init
git add .
git commit -m "APEX server edition"
gh repo create apex-server --private --source=. --push
```

(если `gh` не установлен — создай пустой приватный репозиторий на
github.com вручную, потом `git remote add origin <url>` и `git push -u origin main`)

### 2. Деплой на Railway

1. Зайти на railway.app → New Project → Deploy from GitHub repo → выбрать
   `apex-server`.
2. Railway сам увидит `package.json` и `npm start` — ничего настраивать не
   нужно, задаст `PORT` через переменную окружения автоматически.
3. Settings → Networking → Generate Domain — получишь публичную ссылку
   вида `apex-server-production.up.railway.app`. Это и есть твой дашборд,
   открывается с телефона.
4. Deployments → там же видно логи в реальном времени (то же самое, что
   `console.log` внутри `server.js`).

### Деньги

Railway больше не бесплатен просто так: 30 дней триала с $5 кредита без
карты, дальше — Free-план $1/мес (0.5GB RAM, логи хранятся 3 дня) либо
Hobby $5/мес. Наш бот лёгкий (без базы данных, состояние — один JSON-файл),
должен укладываться в $1/мес план. Смотри usage-дашборд в Railway первую
неделю, чтобы не было сюрпризов.

### Persistence (важно!)

По умолчанию файловая система на Railway **эфемерная** — при передеплое
(новый `git push`) `data/state.json` сотрётся, баланс и история сделок
обнулятся. Если хочешь, чтобы прогресс переживал редеплои:

Railway → твой сервис → Settings → Volumes → Add Volume, mount path
`/app/data`. После этого `data/state.json` будет жить между деплоями.
Без volume — переживает обычные рестарты контейнера (краши, засыпание),
но не ручной `git push`.

## Что дальше

- `/api/state` — весь текущий стейт в JSON, если захочешь подключить второй
  дашборд или Telegram-бота с уведомлениями поверх.
- `/api/resume` (POST) — сброс hard-stop, аналог кнопки в браузерной версии.
  Без авторизации — это ок для личной игрушки с paper-деньгами, но если
  когда-нибудь дойдёт до реальных денег, здесь нужен как минимум токен в
  заголовке, эту ссылку никто не должен уметь дёргать кроме тебя.
- Второй проект (металлы/новости) можно поднять как отдельный сервис в том
  же Railway-проекте — те же деньги за инстанс, разные ссылки, смотришь оба
  дашборда параллельно с телефона.
